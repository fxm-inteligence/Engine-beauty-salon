# Beauty Salon

Образец проекта, сгенерированного в FxM Engine: **запись в салон красоты с Telegram-ботом**. Правила записи (рабочие часы мастеров, занятое время, переходы статусов, защита от удаления, напоминание клиенту) заданы блоками бизнес-логики на холсте, а не написаны руками. Сервер, база, сайт и бот выгружены из Engine без ручных правок.

> Собрано в [FxM Engine](https://engine.fxm-int.space). В «Новом проекте» есть галерея из 27 готовых заготовок: сайты, магазины, запись и бронирование, боты, системы для бизнеса. Из любой можно начать свой проект и забрать код в Git. Салон с ботом — одна из них («Салон красоты» в разделе записи).

Это **каркас, а не готовый продукт**. Раздел «Чего здесь нет» стоит прочитать до того, как сравнивать с готовыми сервисами записи.

## Что внутри

| Часть | Папка | Технологии | Что это |
|---|---|---|---|
| База данных | `database/` | Prisma, PostgreSQL | Таблицы услуг, мастеров и записей; запись ссылается на услугу и мастера внешними ключами |
| Сервер | `backend/` | NestJS | Услуги, мастера, записи, журнал статусов и журнал изменений; правила записи; напоминание клиенту в Telegram |
| Сайт | `frontend/` | Next.js, Tailwind | Главная: список услуг и форма записи; страница мастеров |
| Telegram-бот | `telegram/` | Telegraf | Команды `/start`, `/book`, `/mybookings`: выбор услуги, мастера, дня и свободного времени |

## Как проходит запись

- **Услуги** (название, длительность в минутах, цена) и **мастера** (имя, рабочие часы, выходные дни) читает любой посетитель, менять их может только администратор по ключу.
- **Запись** создаёт любой посетитель сайта или бота: услуга, мастер, имя, время.
- Сервер сам отклоняет запись **вне рабочих часов мастера**, **в его выходной** и **на занятое время**. Длительность берётся из услуги, поэтому 60-минутная услуга занимает час.
- Рабочие часы мастера пишутся строкой `mon-fri 10:00-20:00; sat 10:00-16:00`, выходные дни — датами `2026-12-31`. Если часы мастера не заданы, действуют общие `mon-sat 10:00-20:00`.
- Часы считаются по времени **Europe/Moscow**. Чтобы сменить пояс, поменяйте свойство `timezone` у блока Slot Check на холсте и сгенерируйте проект заново.
- Статус записи идёт `new → confirmed → done`, отменить можно из `new` и `confirmed`. Прыжок `new → done` сервер отклоняет, каждое изменение остаётся в журнале.
- Услугу или мастера, у которых есть записи, удалить нельзя.
- Клиенту, который записался через бота, бот пишет «Вы записаны», а за 3 часа до визита присылает напоминание (один раз). Срок меняется переменной `REACTION_REMIND_CLIENT_BEFORE`.

## Что проверено

Всё ниже проверено запуском на собранных контейнерах, не по чтению кода:

- списки услуг и мастеров открыты без ключа, список записей закрыт (403);
- запись без ключа проходит (201); запись вне часов мастера, в воскресенье, в выходной день и на занятое время отклоняется (409);
- свободные окна считаются по часам мастера и по уже занятому времени;
- переход `new → done` отклоняется (409), `new → confirmed` проходит, журнал статусов и журнал изменений заполняются;
- услугу и мастера с записями удалить нельзя (409);
- сообщение «Вы записаны» и напоминание уходят в Telegram, напоминание один раз;
- форма на сайте создаёт запись на сервере;
- бот проходит весь диалог: `/start`, `/book`, выбор услуги, мастера, дня и времени, запись создаётся, `/mybookings` показывает её.

**Как именно проверялось Telegram:** вместо настоящего Telegram стоял подставной сервер на той же машине, который принимает вызовы Bot API и отдаёт боту нажатия кнопок. С настоящим Telegram и настоящим токеном проект **не запускался**.

## Чего здесь нет

- **Нет входа и панели администратора.** Услуги, мастеров и их часы добавляют запросами к API с ключом `ADMIN_KEY` (примеры ниже). Подтвердить или отменить запись так же можно только через API.
- **Нет оплаты и предоплаты, нет отмены записи самим клиентом** (ни на сайте, ни в боте).
- **Записи с сайта не связаны с Telegram.** `/mybookings` показывает только записи, сделанные через бота: их ищет по Telegram-id отправителя. Сообщение «Вы записаны» и напоминание тоже получают только они.
- **Бот показывает время без часового пояса**: кнопки времени подписаны по Europe/Moscow, а `/mybookings` печатает время в UTC (`2026-11-11T16:30:00.000Z`).
- **Сайт не показывает свободное время мастера.** Он принимает дату и время в форме, а сервер сам отвечает 409, если оно занято. Свободные окна считает `/bookings/free`; им пользуется бот, этот маршрут требует ключ.
- **Бот не входит в `docker-compose.yml`**, его запускают отдельно (см. ниже).
- Сайт собран и открывается, форма записи отправляется; автотесты сайта (`frontend/e2e`) я не запускал.
- Никакого мониторинга, резервных копий и защиты от спама: каркас.

## Быстрый старт

1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) и запустите его.
2. Скопируйте `backend/.env.example` в `backend/.env` и впишите в `ADMIN_KEY` длинную случайную строку (ключ администратора).
3. В корне проекта: `docker compose up --build`. Первая сборка занимает несколько минут.
4. Сайт: http://localhost:3000, сервер: http://localhost:3001.

Остановить: `Ctrl+C`; следующий `docker compose up` вернёт всё с сохранёнными данными.

## Услуги и мастера

В примерах `KEY` — ваш `ADMIN_KEY`, `curl` из терминала:

```bash
curl -X POST http://localhost:3001/treatments -H "x-api-key: KEY" -H "content-type: application/json" \
  -d '{"name":"Маникюр","minutes":60,"price":1500}'

curl -X POST http://localhost:3001/masters -H "x-api-key: KEY" -H "content-type: application/json" \
  -d '{"name":"Анна","hours":"mon-fri 10:00-20:00; sat 10:00-16:00","daysOff":"2026-12-31"}'
```

Подтвердить запись: `PATCH /bookings/<id>` с телом `{"status":"confirmed"}`; какие переходы доступны сейчас — `GET /bookings/<id>/transitions`.

## Telegram-бот

1. Создайте бота у [@BotFather](https://t.me/BotFather) и возьмите токен.
2. В `backend/.env` впишите `TELEGRAM_BOT_TOKEN=<токен>`, чтобы сервер мог писать клиентам («Вы записаны» и напоминание), и перезапустите `docker compose up -d`.
3. Запустите бота:

```bash
cd telegram
npm install
npm run build
BOT_TOKEN=<токен> API_URL=http://localhost:3001 API_KEY=<ADMIN_KEY> npm start
```

Бот ходит к серверу с ключом `ADMIN_KEY`, поэтому держите его на доверенной машине.

## API

| Маршрут | Кто может | Что делает |
|---|---|---|
| `GET /treatments`, `GET /masters` | все | списки услуг и мастеров |
| `POST /bookings` | все | создать запись |
| `GET /bookings`, `GET /bookings/:id` | ключ | записи (фильтр, например `?clientTelegramId=…`) |
| `GET /bookings/free?masterId=…&date=YYYY-MM-DD` | ключ | свободные окна мастера в этот день |
| `GET /bookings/busy` | ключ | занятое время |
| `PATCH /bookings/:id`, `GET /bookings/:id/transitions` | ключ | сменить статус, посмотреть доступные переходы |
| `POST/PUT/PATCH/DELETE /treatments`, `/masters` | ключ | управление услугами и мастерами |
| `GET /booking-status-logs`, `GET /booking-audit-logs` | ключ | журналы статусов и изменений |

## Куда писать свой код

Здесь код **получен генератором**: правила записи живут в блоках холста, а не в этих файлах. Исправления в сгенерированных файлах пропадут при следующей генерации. Свой код пишите так:

- правила записи, напоминания и тексты бота меняйте на холсте Engine и генерируйте проект заново;
- если вы отходите от Engine насовсем, проект открывается в любой IDE и развивается как обычный NestJS, Next.js и Telegraf.

Исходное описание проекта лежит в `project.json`; из него Engine собирает холст.
